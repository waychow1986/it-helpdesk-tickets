# 内部 IT 工单系统 V2 业务意图

## 摘要

提出方（claude，受 eric 委托）要求在已上线的内部 IT 工单系统 V1 基础上升级为 V2：每张工单按紧急程度自动获得"期望解决时间"并在列表和详情中显示，超时未解决的工单醒目标出，V1 已有工单也要补上期望解决时间；管理员可以停用和重新启用账号；周报表新增"本周超时解决的工单数量"；升级在 V1 线上数据基础上直接进行，所有既有数据保持不变、按原权限可查看，升级过程可安全重复执行。request 列出的四项均为本次必须交付的范围，未给出更细的优先级排序。

## 业务问题与机会

- V1 中工单只有紧急程度，没有处理时限，IT 同事和员工无法判断一张工单是否已经拖延，超时工单也无法被及时发现。
- IT 主管的周报表只反映积压（超过 3 天未解决），无法反映本周有多少工单是超出时限才解决的，难以衡量处理时效。
- V1 只能创建账号、不能停用账号；人员离职或调岗后其账号仍可登录，离开的 IT 同事也仍出现在可分派名单中，存在误分派和安全隐患。
- V1 已在线上使用并积累了账号、类别、工单、沟通和处理记录；若升级导致数据丢失、改变或权限错乱，将失去业务记录与统计依据。

## 期望业务结果

- **INT-001**：每张工单都有明确的期望解决时间，员工和 IT 同事能直观看到工单是否已超时未解决，从而及时处理拖延的工单。
- **INT-002**：离开或不再需要使用系统的人员账号可以被停用，停用后无法登录，也不会再被分派工单，同时其历史工单与沟通记录完整保留。
- **INT-003**：IT 主管每周能够从报表中看到本周超时解决的工单数量，用于衡量处理时效。
- **INT-004**：系统从 V1 平滑升级到 V2，V1 线上的全部既有数据保持不变并按原权限可查看，升级过程可以安全地重复执行。

## 受影响用户与系统

- 员工（工单提交人）：在自己的工单列表和详情中看到期望解决时间及超时标识；账号可能被管理员停用。
- IT 同事（处理人）：在工单列表和详情中看到期望解决时间及超时标识；被停用的 IT 同事不再出现在可分派对象中。
- 管理员：新增停用和重新启用账号的能力；查看包含新增统计项的周报表。
- IT 主管：仍通过管理员角色查看周报表（沿用 V1 已确定的业务决定），报表新增"本周超时解决的工单数量"。
- 既有业务系统：已上线的内部 IT 工单系统 V1 及其线上数据（账号、类别、工单、沟通记录、处理记录）是本次升级的对象；request 未提及对接其他公司系统。

## 业务能力与范围

### 范围内

- **INT-005**：每张工单根据紧急程度自动给出期望解决时间：高 4 小时、中 1 个工作日、低 3 个工作日；时间按自然时间计算（request 原文："时间按自然时间计算即可"）：1 个工作日按 24 小时、3 个工作日按 72 小时计算，均自工单提交时刻起算，不扣除夜间、周末和节假日（BQ-001 人工答案）。
- **INT-006**：工单列表和工单详情显示期望解决时间。
- **INT-007**：超过期望解决时间仍未解决（状态为待处理或处理中）的工单在列表和详情中醒目标出。
- **INT-008**：V1 已有的工单按各自的紧急程度和提交时间、采用与新工单相同的口径（INT-005）补上期望解决时间。
- **INT-009**：管理员可以停用账号，也可以重新启用已停用的账号。
- **INT-010**：账号停用后不能登录系统。
- **INT-011**：账号停用后不再出现在可分派的 IT 同事里。
- **INT-012**：被停用账号历史上提交或处理过的工单、沟通记录照常保留和显示。停用 IT 同事时，其名下尚未解决的工单不自动改动，仍显示其为处理人，由其他 IT 同事重新认领或分派，与 V1 取消 IT 同事身份时的处理一致（BQ-003 人工答案）。
- **INT-013**：周报表增加一项：本周超时解决的工单数量，即本周（当前自然周）内首次被标记为"已解决"、且首次标记为已解决的时刻晚于其期望解决时间的工单数量，与 V1 报表"首次标记为已解决"的口径一致（BQ-002 人工答案）。
- **INT-014**：在 V1 的线上数据基础上直接升级，升级后所有账号、类别、工单、沟通和处理记录保持不变，并且按原权限可以查看；升级不能丢失或改变任何已有数据（为既有工单补上期望解决时间除外）。
- **INT-015**：升级过程可以安全地重复执行。

### 范围外

以下内容 request 未提出，本次不纳入范围（如需纳入须由业务方另行提出）：

- 超时的邮件、即时消息等外部通知、提醒或自动升级。
- 按工作日 / 节假日日历计算期望解决时间。
- 由人手工设置或修改单张工单的期望解决时间；按类别等其他条件设定不同时限。
- 删除账号；员工自助停用账号。
- 改变 V1 已有的周报表四项统计口径。
- V1「范围外」中列出、本次 request 未重新提出的其他能力（如附件、对接公司现有登录系统、自动分派、移动端原生应用等）。

## 业务约束与优先级

- 期望解决时间：高 4 小时、中 1 个工作日、低 3 个工作日，时间按自然时间计算（request 原文）；1 个工作日 = 24 小时、3 个工作日 = 72 小时，自提交时刻起算（BQ-001 人工答案）。
- 停用账号后其历史上提交或处理过的工单、沟通记录必须照常保留和显示。
- 升级必须在 V1 线上数据基础上直接进行，所有账号、类别、工单、沟通和处理记录保持不变并按原权限可查看；升级过程可安全地重复执行。
- 沿用 V1 已确定的业务决定：系统内自建账号、由管理员统一创建、不开放自助注册；身份分为员工、IT 同事、管理员三种，IT 主管查看报表的权限由管理员角色承担；工单状态固定为待处理、处理中、已解决、已关闭四种，"未解决"指状态为待处理或处理中。
- 优先级：request 所列四项能力均为 V2 必需范围，未提出时间、预算或分阶段要求。

## 已知事实、依赖与风险

### 已知事实

- V1 已上线，紧急程度为固定三级"低、中、高"，工单提交后紧急程度和提交时间不可修改。
- V1 中工单状态可在四种状态间任意修改，已解决的工单可以被改回待处理或处理中。
- V1 周报表已包含四项：每个类别的工单数量、平均处理时长、每位 IT 同事处理量、超过 3 天未解决的工单数；其中"处理量"和"平均处理时长"以工单"首次标记为已解决"的时刻为准，统计范围为当前自然周。
- V1 中管理员可以取消 IT 同事身份，被取消者不再出现在可分派对象中，其名下工单仍显示其为处理人，直到被重新认领或分派。
- V1 不提供删除工单、沟通记录或处理记录的功能。

### 业务依赖

- 依赖 V1 线上环境及其现有数据可用于直接升级。
- 需要管理员判断并执行具体哪些账号需要停用或重新启用。

### 风险

- V1 已有工单补上期望解决时间后，大量历史未解决工单可能一次性显示为超时，可能让使用者短期内看到较多超时标识。
- 停用 IT 同事时其名下未解决工单不自动改动（BQ-003 人工答案），若无人及时重新认领或分派，这些工单可能被拖延。
- 若停用的是唯一的管理员账号，系统可能无人能继续管理账号；request 未对此作出要求。
- 升级直接作用于线上数据，若升级失败或重复执行产生副作用，将影响已有业务记录。

## 开放业务问题

当前无阻塞业务问题。以下问题已由人工澄清答案（HT-DLV-20261117-88E4DAE97F6A-0001，claude 受 eric 委托）回答：

- [x] **BQ-001** "中 1 个工作日、低 3 个工作日"在"按自然时间计算"下如何换算为期望解决时间？（状态：已解决；人工答案：A——1 个工作日按自然时间 24 小时、3 个工作日按 72 小时计算，均自提交时刻起算，与 V1"超过 3 天"的 72 小时口径一致；影响：INT-005、INT-007、INT-008、INT-013）
  - **A（推荐）**：1 个工作日按自然时间 24 小时计算、3 个工作日按 72 小时计算，均自提交时刻起算，不扣除夜间、周末和节假日；与 request"按自然时间计算即可"及 V1"超过 3 天未解决"按 72 小时计算的口径一致。
  - **B**：1 个工作日按 8 小时计算、3 个工作日按 24 小时计算，均为自提交起的自然时间。
  - **C**：按工作日日历计算（跳过周末，期望解决时间落在下一个或第三个工作日的同一时刻）。
- [x] **BQ-002** 周报表中"本周超时解决的工单数量"如何统计？（状态：已解决；人工答案：A——统计本周首次被标记为"已解决"且首次标记时刻晚于期望解决时间的工单，与 V1 报表"首次标记为已解决"的口径一致；影响：INT-013）
  - **A（推荐）**：统计本周（自然周）内首次被标记为"已解决"、且首次标记为已解决的时刻晚于其期望解决时间的工单数量；与 V1 报表"首次标记为已解决"的口径一致。
  - **B**：统计本周内被标记为"已解决"（含再次标记已解决）且该时刻晚于期望解决时间的工单数量，同一工单本周内只计一次。
  - **C**：A 的口径之外，状态被改为"已关闭"且关闭时刻晚于期望解决时间的工单也计为超时解决。
- [x] **BQ-003** 停用一位 IT 同事时，其名下仍未解决的工单如何处理？（状态：已解决；人工答案：A——保持原处理人，由其他 IT 同事重新认领或分派，不自动改动工单，与 V1 取消 IT 同事身份时的处理一致；影响：INT-011、INT-012）
  - **A（推荐）**：工单保持原样，仍显示该同事为处理人，由其他 IT 同事重新认领或分派；与 V1 取消 IT 同事身份时的处理一致。
  - **B**：停用时其名下未解决工单自动变为"未分配"，处理记录中保留原处理人信息。
  - **C**：其名下仍有未解决工单时不允许停用，须先将工单转给其他 IT 同事。
