# 内部 IT 工单系统业务意图

## 摘要

公司内部（提出方：eric）需要一个网页形式的 IT 工单系统：员工遇到电脑、网络、账号、软件安装等 IT 问题时在网页上提交工单，IT 同事负责认领、分派、处理和回复，管理员维护工单类别和 IT 同事名单，IT 主管每周查看工单统计报表。工单和处理记录需要长期保存，系统升级或重新部署后历史数据不能丢失。本交付为 V1，request 中列出的全部能力均为本次必须交付的范围，未给出更细的优先级排序。

## 业务问题与机会

- 员工的 IT 问题目前缺少统一的网页提交与跟踪渠道，员工无法自助查看自己问题的处理进度，IT 同事也缺少集中查看、认领和分派问题的地方。
- 工单数量会越来越多，若不能按关键词和条件检索，IT 同事将难以定位历史或在办工单。
- IT 主管每周需要掌握各类别工单量、平均处理时长、每位 IT 同事处理量以及超过 3 天未解决的积压情况；没有统一记录就无法形成这些报表，也无法发现积压。
- 工单和处理记录需要作为长期留存的业务记录，若在升级或重新部署时丢失，将失去历史追溯和统计依据。

## 期望业务结果

- **INT-001**：公司员工遇到电脑、网络、账号、软件安装之类的 IT 问题时，能够通过网页提交工单，并由 IT 同事负责处理。
- **INT-002**：员工提交工单后可以随时看到自己所有工单的处理进度，并能在工单下补充说明。
- **INT-003**：IT 同事能够集中查看全部工单，通过认领或分派明确每张工单的处理人，并推进工单状态、与提交人沟通。
- **INT-004**：随着工单数量增长，员工和 IT 同事仍能通过关键词搜索和条件筛选快速找到所需工单。
- **INT-005**：IT 主管每周能够获得反映工单量、处理效率、人员工作量和积压情况的报表。
- **INT-006**：工单和处理记录长期保存，系统升级或重新部署之后以前的数据不丢失。

## 受影响用户与系统

- 员工（工单提交人）：提交工单、查看自己工单的处理进度、在自己的工单下补充说明；只能看到自己提交的工单。
- IT 同事（处理人）：查看全部工单、认领或分派工单、修改工单状态、在工单下回复。
- 管理员：维护工单类别，设置哪些人是 IT 同事。
- IT 主管：每周查看工单统计报表。
- 既有业务系统：request 未提及需要对接的公司既有系统（如公司统一账号或通讯工具）；员工身份如何识别见开放业务问题 BQ-001。

## 业务能力与范围

### 范围内

- **INT-007**：员工在网页上提交工单，提交时填写标题、问题描述、类别和紧急程度。
- **INT-008**：员工提交后可以看到自己所有工单的处理进度。
- **INT-009**：员工可以在自己的工单下面补充说明。
- **INT-010**：员工只能看到自己提交的工单。
- **INT-011**：IT 同事可以查看全部工单。
- **INT-012**：IT 同事可以认领工单，或将工单分派给其他 IT 同事。
- **INT-013**：IT 同事可以修改工单状态，状态包括：待处理、处理中、已解决、已关闭。
- **INT-014**：IT 同事可以在工单下面回复。
- **INT-015**：系统有管理员角色，管理员可以维护工单类别。
- **INT-016**：管理员可以设置哪些人是 IT 同事。
- **INT-017**：可以按关键词搜索工单，输入标题或描述里的一部分文字就能找到对应工单。
- **INT-018**：可以按状态、类别、处理人、提交时间筛选工单。
- **INT-019**：IT 主管每周查看报表，报表包含：每个类别的工单数量、平均处理时长、每个 IT 同事处理了多少单、还有多少超过 3 天没解决的工单。
- **INT-020**：工单和处理记录长期保存，系统升级或者重新部署之后，以前的数据不能丢失。

### 范围外

以下内容 request 未提出，本次不纳入范围（如需纳入须由业务方另行提出）：

- 邮件、即时消息等外部通知或提醒。
- 工单附件（截图、文件）上传。
- SLA 承诺、自动升级或自动分派规则。
- 员工满意度评价、知识库、资产管理。
- 移动端原生应用。
- 与公司其他既有系统的集成（员工身份识别方式待 BQ-001 确认）。

## 业务约束与优先级

- 系统以网页形式供员工提交和查看工单（request 原文："在网页上提交工单"）。
- 工单状态固定为四种：待处理、处理中、已解决、已关闭。
- 员工只能看到自己提交的工单；IT 同事可以查看全部工单。
- 报表按周供 IT 主管查看，积压口径为"超过 3 天没解决"。
- 工单和处理记录需长期保存，升级或重新部署不得导致历史数据丢失。
- 优先级：request 所列能力均为 V1 必需范围，未提出时间、预算或分阶段要求。

## 已知事实、依赖与风险

### 已知事实

- 工单类别示例：电脑、网络、账号、软件安装；类别由管理员维护，可增减。
- 提交工单需填写的信息：标题、问题描述、类别、紧急程度。
- 系统角色：员工、IT 同事、管理员、IT 主管。
- 工单下存在双向沟通记录：员工补充说明、IT 同事回复。
- 工单数量会持续增长。
- 项目定位为"带数据库的业务系统（工单管理）"（见仓库 README）。

### 业务依赖

- 需要业务方确认员工和各角色身份的来源（见 BQ-001）。
- 需要管理员提供初始的工单类别清单和 IT 同事名单。
- 需要业务方确认报表口径（见 BQ-002、BQ-003）。

### 风险

- 若员工身份识别方式与公司现有账号体系不一致，可能导致员工误看他人工单或使用门槛过高，影响"员工只能看到自己提交的工单"这一要求。
- 报表口径（"3 天"如何计算、每周报表统计哪些工单、"处理时长"的起止点）未明确时，报表结果可能与 IT 主管预期不符。
- request 未说明紧急程度的分级，也未说明 IT 主管是否同时属于 IT 同事或管理员；若后续出现与当前理解不同的要求，可能需要调整范围。
- 工单数量持续增长，若检索能力不足将影响 IT 同事日常使用。

## 开放业务问题

- [ ] **BQ-001** 员工、IT 同事、管理员和 IT 主管如何登录并被识别身份？（状态：待澄清；影响：INT-001、INT-010、INT-016）
  - **A（推荐）**：使用公司现有统一账号登录（如企业目录 / SSO），员工无需另行注册；推荐理由：员工身份可靠，便于保证"员工只能看到自己工单"，也便于管理员从现有人员中设置 IT 同事。
  - **B**：系统内自建账号，由管理员创建或员工自行注册。
  - **C**：系统内自建账号，由管理员统一创建，不开放自助注册。
- [ ] **BQ-002** 报表中"超过 3 天没解决"的 3 天如何计算、"没解决"指哪些状态？（状态：待澄清；影响：INT-019）
  - **A（推荐）**：按自然日计算（自提交起超过 72 小时），状态仍为待处理或处理中的工单计为未解决；推荐理由：口径最简单直观，无需维护工作日历。
  - **B**：按工作日计算（扣除周末与节假日），状态仍为待处理或处理中的工单计为未解决。
- [ ] **BQ-003** 每周报表的统计范围和"平均处理时长"的口径是什么？（状态：待澄清；影响：INT-019）
  - **A（推荐）**：工单数量与人员处理量统计本周（自然周）内提交或解决的工单；平均处理时长按"提交 → 首次标记为已解决"计算；积压数为报表查看时点的实时数量；推荐理由：符合"每周看报表"的使用方式，口径清晰。
  - **B**：报表可由 IT 主管自选任意时间范围，口径同 A。
  - **C**：报表统计系统中全部历史工单（累计口径），平均处理时长按"提交 → 已关闭"计算。
