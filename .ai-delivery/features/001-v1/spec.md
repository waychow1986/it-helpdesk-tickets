# 内部 IT 工单系统产品规格

## 产品目标与边界

本规格把已批准 Intent（INT-001～INT-024）转化为技术无关、可观察、可验收的产品行为，适用于 V1 交付。

- **目标**：员工通过网页提交和跟踪 IT 问题（INT-001、INT-002）；IT 同事集中查看、认领 / 分派、推进状态并与提交人沟通（INT-003）；员工和 IT 同事可按关键词与条件找到工单（INT-004）；IT 主管（通过管理员角色）每周查看统计报表（INT-005）；工单与处理记录长期保存，升级或重新部署后不丢失（INT-006）。
- **边界内**：管理员创建账号与设置 IT 同事、维护工单类别（INT-015、INT-016、INT-021、INT-022）；工单提交、查看、补充说明、回复、认领、分派、状态修改（INT-007～INT-014）；关键词搜索与条件筛选（INT-017、INT-018）；周报表（INT-019、INT-023、INT-024）；数据持久保留（INT-020）。
- **边界外**：外部通知、附件、SLA / 自动分派、满意度 / 知识库 / 资产管理、移动端原生应用、对接公司现有登录系统或其他既有系统、自助注册、独立 IT 主管角色、按工作日计算积压、自选时间范围报表（Intent「范围外」）。

## 参与者与权限

| 参与者 | 身份 | 允许的操作 | 不允许的操作 |
|---|---|---|---|
| 员工 | 员工 | 登录；提交工单；查看、搜索、筛选**本人提交**的工单；在本人工单下补充说明 | 查看他人工单；认领、分派、修改状态；维护类别；设置 IT 同事；创建账号；查看报表 |
| IT 同事 | IT 同事 | 登录；查看、搜索、筛选全部工单；认领；分派给其他 IT 同事；修改状态；在任意工单下回复 | 维护类别；设置 IT 同事；创建账号；查看报表 |
| 管理员 | 管理员 | 登录；创建账号；设置 / 取消 IT 同事身份；维护工单类别；查看周报表 | 本规格未授予管理员提交或处理工单的能力（见假设 A-004） |
| IT 主管 | 使用管理员身份 | 与管理员相同（INT-022：报表查看权限由管理员角色承担） | 同管理员 |
| 未登录访问者 | 无 | 仅可访问登录入口；系统尚未设置初始管理员时，还可使用登录入口处的一次性"设置初始管理员"流程（FR-031，PQ-003 人工答案 A） | 访问任何工单、类别、账号或报表数据；自助注册；初始管理员设置完成后再使用"设置初始管理员"流程 |

权限依据：INT-010、INT-011～INT-016、INT-019、INT-021、INT-022、人工审批意见 HT-DLV-20261116-72F2B9041E74-0011、PQ-003 人工答案 A；宪章「安全与隐私」条款"验证输入、执行 least privilege"。

## 用户故事

### US-001 管理员创建账号并区分身份（P1）

作为管理员，我希望在系统内为员工、IT 同事和管理员统一创建账号并指定身份，以便每个人用自己的账号登录并只获得与身份相符的能力。（INT-021、INT-022）

### US-002 管理员设置 IT 同事（P1）

作为管理员，我希望设置哪些人是 IT 同事、也能取消其 IT 同事身份，以便工单只由 IT 同事处理。（INT-016）

### US-003 管理员维护工单类别（P1）

作为管理员，我希望新增、修改和移除工单类别，以便员工提交时能选择合适的类别。（INT-015）

### US-004 员工提交工单（P1）

作为员工，我希望在网页上填写标题、问题描述、类别和紧急程度提交工单，以便 IT 同事处理我的问题。（INT-001、INT-007）

### US-005 员工跟踪自己的工单并补充说明（P1）

作为员工，我希望随时看到自己所有工单的处理进度和沟通记录，并在工单下补充说明，同时我的工单不被其他员工看到。（INT-002、INT-008、INT-009、INT-010）

### US-006 IT 同事查看、认领与分派工单（P1）

作为 IT 同事，我希望查看全部工单，认领工单或分派给其他 IT 同事，以便每张工单都有明确处理人。（INT-003、INT-011、INT-012）

### US-007 IT 同事推进状态并回复（P1）

作为 IT 同事，我希望修改工单状态并在工单下回复，以便推进处理并与提交人沟通。（INT-003、INT-013、INT-014）

### US-008 搜索与筛选工单（P1）

作为员工或 IT 同事，我希望输入标题或描述中的部分文字搜索工单，并按状态、类别、处理人、提交时间筛选，以便在工单越来越多时仍能快速找到目标工单。（INT-004、INT-017、INT-018）

### US-009 IT 主管查看周报表（P1）

作为使用管理员身份的 IT 主管，我希望每周查看各类别工单数量、平均处理时长、每位 IT 同事处理量和超过 3 天未解决的工单数，以便掌握工作量和积压。（INT-005、INT-019、INT-022、INT-023、INT-024）

### US-010 数据在升级或重新部署后保留（P1）

作为系统的所有使用者，我希望工单和处理记录长期保存，系统升级或重新部署后历史数据仍完整可见。（INT-006、INT-020）

## 功能需求

**账号与身份**

- **FR-001**：账号只能由管理员在系统内创建；创建时指定登录名、初始登录凭据、显示姓名和身份（员工 / IT 同事 / 管理员之一）。系统不提供任何自助注册入口。登录名在系统内唯一，重复时拒绝创建并提示。
- **FR-002**：用户必须使用管理员创建的账号登录后才能使用系统功能；登录失败（账号不存在或凭据错误）时给出不泄露具体原因差异的失败提示且不进入系统；未登录时访问任何功能页面或数据均被拒绝并引导到登录入口。用户可以主动退出登录。
- **FR-003**：每个账号在任一时刻恰好具有一种身份：员工、IT 同事或管理员；用户登录后只能看到并使用其身份被允许的功能（见「参与者与权限」）。
- **FR-031**：系统在任一新部署的环境（含候选环境）中首次投入使用、尚未设置初始管理员时，登录入口提供一次性"设置初始管理员"流程（PQ-003 人工答案 A）：业务方在该流程中自行设置初始管理员的登录名、登录凭据和显示姓名，设置成功后即可用该凭据以管理员身份登录，完成账号创建、类别维护、IT 同事设置和报表查看。获得初始凭据的全过程不需要任何人手工修改系统保存的数据或系统配置（人工审批意见 HT-DLV-20261116-72F2B9041E74-0011）。该流程的输入校验同 FR-001（登录名、凭据、姓名不能为空），校验失败时不创建账号、流程仍可用。初始管理员设置成功后，该流程永久不可用：登录入口不再显示该流程，直接访问也被拒绝，不能用于新增或接管任何账号；该流程只能创建管理员身份的账号，不构成员工自助注册入口（INT-021）。初始凭据不在页面中回显，也不以明文写入日志。
- **FR-004**：管理员可以把员工身份的账号设为 IT 同事，也可以把 IT 同事改回员工；变更后该账号下一次操作即按新身份生效。被取消 IT 同事身份的账号不再出现在可分派对象中、不能再执行 IT 同事操作；其历史上作为处理人的工单保留其姓名作为处理人，直到被重新认领或分派。

**类别维护**

- **FR-005**：管理员可以新增类别、修改类别名称、移除类别。类别名称不能为空，且不能与现有有效类别同名。
- **FR-006**：被移除的类别不再出现在提交工单的类别选项中；已使用该类别的历史工单保留原类别名称，仍可按该类别筛选并计入报表。类别改名后，使用该类别的工单显示新名称。

**提交工单**

- **FR-007**：员工提交工单时必须填写标题、问题描述，并从当前有效类别中选择一个类别、从固定的三级紧急程度“低、中、高”中选择一个级别（PQ-001 人工答案 A）。任一必填项为空或仅含空白时拒绝提交，指出缺失项，并保留已填写内容。
- **FR-008**：工单提交成功后，系统为其分配唯一工单编号，记录提交人和提交时间，初始状态为"待处理"，处理人为空（未分配），并立即出现在提交人的"我的工单"列表和 IT 同事的全部工单列表中。
- **FR-009**：工单提交后，其标题、问题描述、类别、紧急程度和提交人不可被任何人修改；员工通过补充说明提供更多信息。

**员工查看与补充说明**

- **FR-010**：员工的"我的工单"列表显示其本人提交的全部工单（不限状态），每项至少显示工单编号、标题、类别、紧急程度、当前状态、处理人（或"未分配"）和提交时间。
- **FR-011**：员工可以打开本人工单的详情，看到工单全部提交信息、当前状态、当前处理人、按时间顺序排列的沟通记录和处理记录。
- **FR-012**：员工可以在本人提交的工单下添加补充说明，任何状态下均可添加；添加补充说明不改变工单状态和处理人。内容为空或仅含空白时拒绝。
- **FR-013**：员工在任何入口（列表、搜索、筛选、详情、直接使用他人工单编号或链接访问）都无法看到或操作他人提交的工单；直接访问他人工单时被拒绝，且不显示该工单的任何内容。

**IT 同事处理**

- **FR-014**：IT 同事可以查看全部工单的列表和详情（不限提交人与处理人）。
- **FR-015**：IT 同事可以认领任意工单，认领后处理人变为该 IT 同事本人；已有处理人的工单也可被认领（处理人随之变更）。
- **FR-016**：IT 同事可以把任意工单分派给另一位当前身份为 IT 同事的账号；分派对象只能从当前 IT 同事中选择。
- **FR-017**：IT 同事可以把任意工单的状态修改为待处理、处理中、已解决、已关闭四种之一；状态之间不设流转限制，选择与当前状态相同的值不产生变更。
- **FR-018**：IT 同事可以在任意工单下回复；内容为空或仅含空白时拒绝。回复不改变工单状态和处理人。
- **FR-019**：工单详情中的沟通记录（员工补充说明与 IT 同事回复）按时间先后显示，每条显示作者姓名、作者身份、时间和内容；提交人和所有 IT 同事看到相同的沟通记录。
- **FR-020**：系统为每张工单自动保留处理记录：认领、分派、状态修改，每条记录操作人、操作时间、变更前值与变更后值；处理记录在工单详情中对能查看该工单的用户可见，且不可被编辑或删除。
- **FR-021**：员工不能认领、分派工单或修改工单状态；员工在本人工单详情中看不到这些操作入口，直接发起这些操作时被拒绝且工单不变。

**搜索与筛选**

- **FR-022**：用户可以输入一段文字搜索工单；标题或问题描述中包含该连续文字的工单均被返回（部分匹配，不要求完整词），不包含的不返回。
- **FR-023**：用户可以按状态、类别、处理人（含"未分配"）、提交时间范围筛选工单；多个筛选条件与关键词可同时使用，结果须同时满足全部条件。清除条件后恢复为完整列表。
- **FR-024**：搜索和筛选只在用户可见范围内进行：员工只在本人提交的工单中检索，IT 同事在全部工单中检索。无匹配结果时明确显示"无匹配工单"。

**周报表**

- **FR-025**：管理员可以查看周报表；员工和 IT 同事看不到报表入口，直接访问时被拒绝。
- **FR-026**：周报表展示当前自然周（含报表查看时刻的那一周），并标明该周的起止日期，包含以下四项：
  1. 每个类别的工单数量；
  2. 平均处理时长；
  3. 每位 IT 同事处理的工单数；
  4. 超过 3 天未解决的工单数。
- **FR-027**：报表统计口径（INT-023、INT-024、PQ-002 人工答案 A）：
  - 每个类别的工单数量 = 本周内**提交**的工单按其类别计数（已被移除的类别仍按原类别计入）；
  - 每位 IT 同事处理量 = 本周内**首次被标记为"已解决"**的工单，计入该时刻工单的处理人；该时刻无处理人的工单计入"未分配"一项；首次已解决时刻不在本周内的工单（含本周再次被标记为已解决的工单）不计入；
  - 平均处理时长 = 本周内首次被标记为"已解决"的工单，其"首次标记为已解决时刻 − 提交时刻"的平均值；工单之后再改为其他状态、再次标记已解决，均不改变其"首次已解决"时刻；
  - 本周没有可计入工单的项显示为 0（数量类）或"无数据"（平均处理时长）。
- **FR-028**：超过 3 天未解决的工单数 = 报表查看时刻，状态为"待处理"或"处理中"且"查看时刻 − 提交时刻"超过 72 小时（自然时间，含周末节假日）的全部工单数量，不受本周范围限制；恰好 72 小时不计入。

**数据保存**

- **FR-029**：系统长期保存全部工单、沟通记录、处理记录，以及它们所依赖的账号、身份和类别信息；V1 不提供删除工单、沟通记录或处理记录的功能。
- **FR-030**：系统升级或重新部署后，此前的全部账号、类别、工单（含状态、处理人、提交时间）、沟通记录与处理记录保持不变且可按原权限查看，周报表结果与升级前一致（实时积压项随时间自然变化除外）。

## 产品质量要求

- **NFR-001**（INT-006、INT-020）：数据持久性——任何系统升级或重新部署都不得导致已提交数据丢失或被改变（行为见 FR-029、FR-030）。
- **NFR-002**（INT-001、Intent 业务约束"在网页上提交工单"）：全部用户功能通过网页浏览器使用，不需要安装客户端。

除上述两项外，当前没有获批准的额外质量要求。

## 领域术语

| 术语 | 定义 |
|---|---|
| 工单 | 员工提交的一条 IT 问题记录，含编号、标题、问题描述、类别、紧急程度、提交人、提交时间、状态、处理人 |
| 提交人 | 创建工单的员工账号 |
| 处理人 | 当前负责该工单的 IT 同事；可为空（"未分配"） |
| 认领 | IT 同事把自己设为工单处理人 |
| 分派 | IT 同事把另一位 IT 同事设为工单处理人 |
| 类别 | 管理员维护的工单分类（如电脑、网络、账号、软件安装） |
| 紧急程度 | 提交时从固定三级“低、中、高”中选择的工单紧急级别（PQ-001） |
| 补充说明 | 员工在本人工单下添加的文字 |
| 回复 | IT 同事在工单下添加的文字 |
| 沟通记录 | 某工单全部补充说明和回复的时间序列 |
| 处理记录 | 某工单的认领、分派、状态修改的自动记录 |
| 首次已解决时刻 | 工单第一次被修改为"已解决"状态的时刻 |
| 平均处理时长 | 计入工单的（首次已解决时刻 − 提交时刻）平均值 |
| 积压 / 超过 3 天未解决 | 状态为待处理或处理中，且自提交起超过 72 小时的工单 |
| 自然周 | 周一 00:00 至周日 24:00 的连续 7 天（见假设 A-002） |

## 前置条件与触发条件

- **系统初始状态**：系统首次投入使用时，业务方必须能够获得一个可登录的初始管理员身份，用于创建其他账号（closure：INT-021 要求账号由管理员创建，无此前置条件则无人能创建第一个账号）；初始凭据的获得不得依赖任何人手工修改系统保存的数据或配置（人工审批意见 HT-DLV-20261116-72F2B9041E74-0011）；获得方式为登录入口处的一次性"设置初始管理员"流程（PQ-003 人工答案 A，见 FR-031）。
- **提交工单前置**：用户已以员工身份登录，且至少存在一个有效类别。没有任何有效类别时，提交页面提示"暂无可选类别，请联系管理员"并不允许提交。
- **处理工单前置**：用户已以 IT 同事身份登录；分派时至少存在另一位 IT 同事。
- **管理与报表前置**：用户已以管理员身份登录。
- **触发**：员工提交 / 补充说明；IT 同事认领 / 分派 / 修改状态 / 回复；管理员创建账号 / 设置身份 / 维护类别 / 打开报表；用户搜索或筛选。报表在每次打开时按当时数据计算。

## 行为模型

### US-001 管理员创建账号

- **正常**：管理员填写登录名、初始凭据、姓名并选择身份 → 账号创建成功，出现在账号列表中 → 新用户用该凭据登录，看到与身份相符的功能（FR-001、FR-002、FR-003；AC-001、AC-002）。
- **错误**：登录名已存在或必填项为空 → 拒绝创建并提示，不产生账号（FR-001；AC-001）。
- **边界**：登录页无注册入口；未登录直接访问功能地址被引导至登录（FR-001、FR-002；AC-002）。
- **错误**：凭据错误 → 登录失败提示，停留在登录入口（FR-002；AC-002）。

- **正常**：在新部署、尚未设置初始管理员的环境中，业务方在登录入口打开"设置初始管理员"流程，设置登录名、凭据和姓名 → 设置成功 → 用该凭据登录，看到管理员功能（FR-031；AC-021）。
- **错误**：设置初始管理员时必填项为空 → 拒绝并提示，不创建账号，流程仍可用（FR-031；AC-021）。
- **边界**：初始管理员设置成功后，登录入口不再显示该流程；直接访问该流程被拒绝，不能新增或接管任何账号（FR-031；AC-021）。

### US-002 管理员设置 IT 同事

- **正常**：管理员把某员工设为 IT 同事 → 该账号获得查看全部工单、认领、分派、改状态、回复的能力，并出现在分派对象中（FR-004；AC-004）。
- **替代**：管理员取消某 IT 同事身份 → 该账号回到员工能力，不再出现在分派对象中；其名下工单仍显示其为处理人（FR-004；AC-004）。

### US-003 管理员维护类别

- **正常**：新增类别 → 员工提交页可选择；改名 → 工单显示新名称（FR-005、FR-006；AC-005）。
- **替代**：移除类别 → 提交页不再出现，历史工单保留原类别并可筛选（FR-006；AC-005）。
- **错误**：名称为空或与有效类别重名 → 拒绝（FR-005；AC-005）。

### US-004 员工提交工单

- **正常**：填写四项必填内容并提交 → 生成编号，状态待处理、处理人未分配，出现在"我的工单"和 IT 同事全部工单列表（FR-007、FR-008；AC-006）。
- **错误**：缺少任一必填项 → 拒绝并指出缺失项，已填内容保留（FR-007；AC-006）。
- **边界**：无有效类别时不可提交（前置条件）；提交后工单基本信息不可修改（FR-009；AC-006）。

### US-005 员工跟踪与补充说明

- **正常**：员工打开"我的工单" → 看到本人全部工单及当前状态、处理人；打开详情 → 看到沟通记录和处理记录（FR-010、FR-011；AC-007）。
- **正常**：员工添加补充说明 → 立即出现在沟通记录中，IT 同事可见；状态不变（FR-012、FR-019；AC-008）。
- **错误**：空补充说明 → 拒绝（FR-012；AC-008）。
- **错误**：员工尝试访问他人工单 → 拒绝，不显示任何内容（FR-013；AC-009）。

### US-006 IT 同事查看、认领与分派

- **正常**：IT 同事看到全部员工提交的工单；认领 → 处理人变为本人；分派 → 处理人变为所选 IT 同事；均产生处理记录，提交人可见新处理人（FR-014、FR-015、FR-016、FR-020；AC-010、AC-011）。
- **替代**：对已有处理人的工单再次认领或分派 → 处理人被替换，处理记录记录前后值（FR-015、FR-016、FR-020；AC-011）。
- **边界**：分派对象列表只包含当前 IT 同事（FR-016；AC-011）。

### US-007 IT 同事推进状态与回复

- **正常**：IT 同事把状态改为处理中 / 已解决 / 已关闭 / 待处理 → 列表与详情立即显示新状态，提交人可见，产生处理记录（FR-017、FR-020；AC-012）。
- **替代**：已解决或已关闭的工单可被改回待处理或处理中（FR-017；AC-012）。
- **正常**：IT 同事回复 → 出现在沟通记录中，提交人可见（FR-018、FR-019；AC-013）。
- **错误**：员工尝试认领 / 分派 / 改状态 → 拒绝，工单不变（FR-021；AC-014）。

### US-008 搜索与筛选

- **正常**：输入标题或描述中的部分文字 → 返回全部包含该文字的可见工单（FR-022、FR-024；AC-015）。
- **正常**：按状态 / 类别 / 处理人（含未分配）/ 提交时间范围筛选，或与关键词组合 → 结果同时满足全部条件（FR-023；AC-016）。
- **边界**：员工检索结果不包含他人工单，即使他人工单含有相同关键词（FR-024；AC-015）。
- **边界**：无匹配 → 显示"无匹配工单"（FR-024；AC-015）。

### US-009 周报表

- **正常**：管理员打开报表 → 看到本周起止日期和四项统计（FR-025～FR-028；AC-017、AC-018）。
- **边界**：本周无数据 → 数量为 0、平均处理时长显示"无数据"（FR-027；AC-017）。
- **边界**：提交已超过 72 小时但已解决 / 已关闭的工单不计入积压；未超过 72 小时的待处理 / 处理中工单不计入积压（FR-028；AC-018）。
- **错误**：员工或 IT 同事访问报表 → 拒绝（FR-025；AC-019）。

### US-010 数据保留

- **正常**：升级或重新部署前后，同一账号登录看到完全相同的工单、沟通记录、处理记录、类别与账号（FR-029、FR-030、NFR-001；AC-020）。

## 业务状态、业务数据规则与不变量

**工单状态**：待处理（初始）、处理中、已解决、已关闭。IT 同事可在四种状态间任意修改（FR-017）。

**不变量**

- **INV-001**：每张工单在任一时刻恰好处于四种状态之一。
- **INV-002**：工单处理人要么为空，要么是被设置时身份为 IT 同事的账号。
- **INV-003**：员工可见的工单集合 = 其本人提交的工单集合。
- **INV-004**：工单编号唯一且创建后不变；标题、描述、类别、紧急程度、提交人、提交时间创建后不变（类别改名时显示名称随之变化）。
- **INV-005**：沟通记录和处理记录只追加，不可编辑或删除；处理记录中的"首次已解决时刻"一旦产生不再改变。
- **INV-006**：每个账号恰有一种身份；登录名唯一。
- **INV-007**：有效类别名称互不相同。
- **INV-008**：升级或重新部署不改变任何已保存数据（NFR-001）。

**业务数据规则**

- 工单必填：标题、问题描述、类别、紧急程度（FR-007）。
- 时间以系统统一的公司本地时间显示和计算（假设 A-002）。

## 错误与恢复行为

| 情形 | 系统行为 | 恢复方式 |
|---|---|---|
| 提交工单缺少必填项 | 拒绝并指出缺失项，保留已填内容 | 补全后重新提交 |
| 补充说明 / 回复为空 | 拒绝 | 填写内容后重新提交 |
| 登录失败 | 提示登录失败，不进入系统 | 使用正确凭据重试，或联系管理员 |
| 未登录访问功能 | 引导到登录入口 | 登录后继续 |
| 新环境尚未设置初始管理员 | 登录入口提供一次性"设置初始管理员"流程（FR-031），不要求人工修改数据或配置 | 业务方通过该流程设置凭据后登录 |
| 初始管理员已设置后再访问"设置初始管理员"流程 | 拒绝，不创建或修改任何账号 | 使用已有管理员账号登录 |
| 越权访问（员工访问他人工单、非管理员访问管理功能或报表、员工执行处理操作） | 拒绝并提示无权限，数据不变、不泄露内容 | 无需恢复 |
| 创建账号登录名重复 / 类别重名或为空 | 拒绝并提示 | 修改后重试 |
| 无有效类别时提交工单 | 提示联系管理员，不允许提交 | 管理员新增类别后再提交 |
| 分派时目标已不是 IT 同事 | 拒绝分派，工单不变 | 刷新后选择当前 IT 同事 |
| 操作因任何原因未成功保存 | 明确提示失败，不显示为成功，数据保持操作前状态 | 用户重试 |

## 安全、隐私与可访问性行为

- **访问控制**（宪章「安全与隐私」"执行 least privilege"；INT-010、INT-022）：所有功能均需登录；各身份只能执行「参与者与权限」中列出的操作；越权请求被拒绝且不泄露数据（FR-002、FR-003、FR-013、FR-021、FR-025）。
- **输入验证**（宪章「安全与隐私」"验证输入"）：必填项、空内容、重名、分派对象身份均被校验（FR-001、FR-005、FR-007、FR-012、FR-016、FR-018）。
- **凭据**（宪章「安全与隐私」"凭据保留在服务端""绝不记录 secret"）：登录凭据（含初始管理员设置流程中输入的凭据）不在任何页面中回显；初始管理员凭据不以明文写入日志（FR-031）。
- 可访问性：当前没有获批准的额外要求。

## 性能、可靠性与其他质量边界

- 可靠性：仅限 NFR-001 数据持久性。
- 性能、容量、可用率：当前没有获批准的额外要求。INT-004 中"工单越来越多仍能快速找到"以 FR-022～FR-024 的检索能力满足，不设数值阈值。

## 成功标准

- **SC-001**：员工可独立完成"登录 → 提交工单 → 查看进度 → 补充说明"，并看到 IT 同事的回复和状态变化（INT-001、INT-002）。
- **SC-002**：每张工单都能通过认领或分派得到明确处理人，并由 IT 同事推进到已解决 / 已关闭（INT-003）。
- **SC-003**：员工任何情况下都看不到他人工单；非管理员无法使用管理功能和报表（INT-010、INT-022）。
- **SC-004**：输入标题或描述的部分文字及任意筛选条件组合，返回且仅返回符合条件的可见工单（INT-004）。
- **SC-005**：管理员打开报表，四项指标与按 INT-023、INT-024 及 PQ-002 人工答案口径对同一数据手工计算的结果一致（INT-005）。
- **SC-006**：升级或重新部署后，此前全部数据完整且不变（INT-006）。
- **SC-007**：业务方在新部署的候选环境中无需任何人手工修改数据或配置，即可通过一次性"设置初始管理员"流程获得初始管理员凭据并以管理员身份登录完成验收（人工审批意见 HT-DLV-20261116-72F2B9041E74-0011、PQ-003 人工答案 A）。

## 验收场景

### IQA-001 管理员创建账号与登录

- **追踪：** INT-021、INT-022 / US-001 / FR-001、FR-002、FR-003 / AC-001、AC-002
- **前置条件：** 存在一个可登录的管理员账号（来源见测试策略「Independent QA 验收」中关于管理员账号来源的说明）。
- **操作：** 1）未登录时访问登录入口，检查有无注册入口；未登录直接访问工单列表地址。2）管理员分别创建员工、IT 同事、管理员各一个合成账号。3）用重复登录名再创建一次。4）用新账号逐一登录、退出；用错误凭据登录一次。
- **预期结果：** 无自助注册入口；未登录访问被引导至登录；三个账号创建成功，重复登录名被拒；各账号登录后只看到与其身份相符的功能；错误凭据登录失败。任一不符即失败。
- **必需证据：** 各步骤页面截图或录屏、账号列表截图。

### IQA-002 员工提交工单与必填校验

- **追踪：** INT-001、INT-007、PQ-001 / US-004 / FR-007、FR-008、FR-009 / AC-006
- **前置条件：** 员工账号 E1、IT 同事账号 T1；至少一个有效类别。
- **操作：** 1）E1 打开提交页，检查紧急程度选项。2）E1 分别留空标题、描述、类别、紧急程度各提交一次。3）E1 以紧急程度“低”“中”“高”各完整填写合成内容提交一张。4）E1 查看详情，确认无修改基本信息入口。5）T1 查看全部工单列表。
- **预期结果：** 紧急程度选项恰好为“低、中、高”三项；缺项提交被拒并指出缺失项且已填内容保留；每张完整提交的工单生成唯一编号、显示所选紧急程度，状态待处理、处理人未分配、提交人与提交时间正确；工单出现在 E1 "我的工单"和 T1 全部列表；基本信息不可修改。
- **必需证据：** 校验提示截图、工单详情与两个列表截图。

### IQA-003 员工查看进度与工单隔离

- **追踪：** INT-002、INT-008、INT-010 / US-005 / FR-010、FR-011、FR-013、FR-024 / AC-007、AC-009
- **前置条件：** 员工 E1、E2 各提交至少 2 张含相同关键词的合成工单，状态各不相同。
- **操作：** 1）E1 打开"我的工单"和各工单详情。2）E1 使用 E2 工单的编号或链接直接访问。3）E1 用两人共有的关键词搜索，并按各条件筛选。
- **预期结果：** E1 列表恰好包含其全部工单并显示正确状态和处理人；直接访问 E2 工单被拒且无任何内容泄露；搜索 / 筛选结果中不出现 E2 工单。
- **必需证据：** 列表、详情、拒绝页面、搜索结果截图。

### IQA-004 补充说明与回复的双向沟通

- **追踪：** INT-002、INT-009、INT-014 / US-005、US-007 / FR-012、FR-018、FR-019 / AC-008、AC-013

- **预期结果：** 空内容均被拒；两条有效记录按时间顺序显示作者、身份、时间、内容，E1 与 T1 看到一致的沟通记录；补充说明与回复不改变状态和处理人；已关闭工单仍可补充说明。
- **必需证据：** 双方视角的详情截图。

### IQA-005 IT 同事查看全部工单、认领与分派

- **必需证据：** 列表、分派选项、详情与处理记录截图。

### IQA-006 状态修改

### IQA-013 周报表数量与处理时长

- **追踪：** INT-005、INT-019、INT-024、PQ-002 / US-009 / FR-025、FR-026、FR-027 / AC-017
- **前置条件：** 测试环境中准备合成工单：覆盖本周与上周提交、本周与上周首次解决、解决后被改回再次解决、多个类别（含本周内被移除的类别）、多个处理人、首次标记已解决时无处理人的工单，且已知其提交时刻与首次已解决时刻；另准备"本周无数据"的情形（可在独立数据集中验证）。

### IQA-014 超过 3 天未解决积压数

- **追踪：** INT-019、INT-023、INT-024 / US-009 / FR-028 / AC-018
- **前置条件：** 合成工单：提交超过 72 小时的待处理、处理中、已解决、已关闭各至少一张；提交未满 72 小时的待处理、处理中各一张；提交早于本周但仍未解决的工单至少一张。

### IQA-016 业务方获得初始管理员凭据并登录

- **追踪：** INT-021、INT-022、人工审批意见 HT-DLV-20261116-72F2B9041E74-0011、PQ-003、人工澄清答案 HT-DLV-20261116-72F2B9041E74-0014 / US-001 / FR-031 / AC-021

## 验收标准

- **AC-001**：管理员能创建三种身份的账号；登录名重复或必填项为空时创建被拒；系统无自助注册入口。
- **AC-002**：只有管理员创建的账号能登录；未登录访问被引导至登录；错误凭据登录失败；用户可退出登录。
- **AC-003**：各身份登录后只看到并只能使用其被允许的功能。
- **AC-004**：管理员设置 / 取消 IT 同事身份后，该账号能力与分派对象列表随之变化，历史处理人保留。
- **AC-005**：类别可新增、改名、移除；空名和重名被拒；移除的类别不可再选，历史工单保留并可被筛选。
- **AC-006**：紧急程度只能选择“低、中、高”之一；员工提交完整工单后生成唯一编号、状态待处理、未分配，并出现在本人列表和 IT 同事列表；缺少必填项被拒且保留已填内容；提交后基本信息不可修改。
- **AC-007**：员工"我的工单"列出本人全部工单的当前状态与处理人，详情显示沟通记录和处理记录。
- **AC-008**：员工可在本人任意状态的工单下补充说明，空内容被拒，补充说明不改变状态与处理人且 IT 同事可见。
- **AC-009**：员工在任何入口都无法看到或访问他人工单。
- **AC-010**：IT 同事能看到全部员工的全部工单。
- **AC-011**：IT 同事能认领或分派给当前 IT 同事，处理人随之改变，处理记录记录前后值。
- **AC-012**：IT 同事能将工单在四种状态间修改，每次修改立即可见并产生处理记录。
- **AC-013**：IT 同事回复出现在沟通记录中，提交人可见，空回复被拒。
- **AC-014**：员工不能认领、分派或修改状态，直接发起被拒且工单不变。
- **AC-015**：关键词搜索返回标题或描述包含该片段的全部可见工单，不返回其他工单；员工仅检索本人工单；无结果时有明确提示。
- **AC-016**：按状态、类别、处理人（含未分配）、提交时间范围的筛选及其与关键词的组合，返回且仅返回同时满足全部条件的工单。
- **AC-017**：周报表标明本周起止日期；类别数量只计本周提交的工单，IT 同事处理量只计本周首次被标记为已解决的工单并归属该时刻处理人（无处理人计入“未分配”）；类别数量、IT 同事处理量、平均处理时长与按该口径手工计算的结果一致；无数据时显示 0 或"无数据"。
- **AC-018**：积压数等于查看时刻状态为待处理 / 处理中且提交超过 72 小时的全部工单数。
- **AC-019**：员工和 IT 同事无法访问报表和任何管理功能。
- **AC-020**：系统升级或重新部署后，全部账号、类别、工单、沟通记录和处理记录完整不变，报表结果一致。V1 不验证升级或重新部署后的数据保留，改到后续迭代通过真实升级来验证（人工澄清答案 HT-DLV-20261116-72F2B9041E74-0014）。
- **AC-021**：在尚无可用管理员的环境中首次部署时，业务方无需任何人手工修改数据或配置，即可通过登录入口的一次性"设置初始管理员"流程设置凭据并以管理员身份登录；必填项为空时设置被拒。已有可用管理员时（含初始管理员设置成功后及之后的候选验证），该流程不再显示、直接访问被拒，不能新增或接管任何账号。首次设置在空环境上的完整行为由开发阶段自动化测试覆盖，候选环境按 IQA-016 所处情形验证（人工澄清答案 HT-DLV-20261116-72F2B9041E74-0014）。

## 测试策略

### 开发者验证

- 对每条 FR 与业务规则进行开发者级验证，重点覆盖：必填与空内容校验、各身份的允许与拒绝操作（含直接发起越权请求）、员工工单隔离、状态任意修改与处理记录、首次已解决时刻不变、关键词部分匹配与筛选组合、报表四项指标的口径与边界（恰好 72 小时、跨周、无数据、再次解决）、类别移除与 IT 同事身份取消后的历史数据。
- 使用合成账号、类别和工单数据，在部署前于开发环境执行；开发者验证结果不能替代 Independent QA 验收。
- "设置初始管理员"流程（FR-031）在尚无可用管理员的空环境上的首次设置完整行为（入口显示、必填校验、设置成功并登录使用管理员功能、设置后入口不显示、直接访问被拒、不能新增或接管账号、凭据不回显）由开发阶段自动化测试覆盖（人工澄清答案 HT-DLV-20261116-72F2B9041E74-0014）。

### Independent QA 验收

- Independent QA 在部署的候选版本上，以黑盒方式（通过网页，以各身份登录）执行 IQA-001～IQA-014 与 IQA-016；IQA-015 不在 V1 执行范围。
- 测试素材全部为合成数据（账号、类别、工单文本、提交时间分布）；IQA-013、IQA-014 需要提交时刻和首次已解决时刻跨越本周 / 上周与 72 小时边界的合成工单，由测试环境的数据准备方式构造，不需要人工提供真实业务数据。
- IQA-015：V1 不验证升级或重新部署后的数据保留，改到后续迭代通过真实升级来验证（人工澄清答案 HT-DLV-20261116-72F2B9041E74-0014）。
- IQA-016 最先执行，全过程不得为改变环境状态而人工修改数据或配置：在尚无可用管理员的环境中首次部署时，验证首次设置的完整流程（PQ-003 人工答案 A）；之后的候选验证（已有可用管理员）验证设置入口不可见、直接访问被拒、不能新增或接管账号（人工澄清答案 HT-DLV-20261116-72F2B9041E74-0014）。
- 其他场景所需的管理员账号来源：处于首次设置情形时，由该初始管理员在系统内创建；已有可用管理员时，由 QA 以测试数据准备方式自备合成管理员账号（不是产品功能，不经"设置初始管理员"流程，不修改或接管环境中他人的账号）。
- IQA-002 按 PQ-001 人工答案（三级：低、中、高）判定紧急程度选项；IQA-013 按 PQ-002 人工答案（类别数量计本周提交、处理量计本周首次解决并归属当时处理人）计算期望值。

### 总体通过与失败标准

- **通过**：V1 执行范围内的 IQA-001～IQA-014 与 IQA-016 全部通过，且每个场景的必需证据齐全；IQA-015 不在 V1 验证范围（改到后续迭代通过真实升级来验证），不计入 V1 通过判定。
- **失败**：任一 IQA 场景的预期结果不满足；或出现越权可见 / 可操作（员工看到他人工单、非管理员访问管理功能或报表）；或升级 / 重新部署后任何数据缺失或改变——以上任一项即判定整体失败，不允许以开发者验证、构建成功或页面可打开代替。

## 假设、依赖与范围外边界

**假设**

- **A-001**：账号管理仅包含创建账号与设置身份；修改密码、重置凭据、停用 / 删除账号不在已批准范围内。
- **A-002**：所有时间按公司统一的本地时间显示与计算；自然周为周一 00:00 至周日 24:00；报表仅展示当前自然周，不提供历史周选择（依据 BQ-003 人工答案 A，B"自选范围"未被采纳）。
- **A-003**：每个账号只有一种身份；IT 同事不提交工单（如需提交，由管理员为其另建员工账号或调整身份）。
- **A-004**：管理员身份只具备账号、身份、类别管理和报表能力，不查看工单明细、不提交或处理工单。
- **A-005**：关键词搜索对英文字母不区分大小写。
- **A-006**：员工在任何状态的本人工单下均可补充说明，且补充说明不会自动改变状态。

**依赖**

- 系统首次投入使用时，业务方通过登录入口的一次性"设置初始管理员"流程获得初始管理员凭据（FR-031；不依赖人工改数据或配置）。
- 管理员提供初始类别清单和 IT 同事名单（Intent 业务依赖）。

**范围外边界**

外部通知、附件上传、SLA / 自动升级 / 自动分派、满意度评价、知识库、资产管理、移动端原生应用、对接公司现有登录系统及其他既有系统、自助注册、独立 IT 主管角色、按工作日计算积压、自选时间范围报表、工单或记录删除。
